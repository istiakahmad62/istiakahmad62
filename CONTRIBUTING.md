# Contributing

Thanks for your interest in contributing! A few guidelines to make the process smooth:

- Issues
  - Search existing issues before creating a new one.
  - Use clear titles and steps to reproduce; include expected vs actual behavior.
  - Add labels and a short reproducible example where applicable.

- Pull Requests
  - Fork the repo and create a feature branch: `feature/short-description` or `fix/short-description`.
  - Keep PRs small and focused; one concern per PR.
  - Include a descriptive PR title and description, and reference any related issue (e.g., `Fixes #123`).
  - Run tests and linters locally before opening a PR.

- Code style & tests
  - Follow existing project conventions (TypeScript, Prettier/ESLint where configured).
  - Add tests for new features or bug fixes. Run the test suite locally before opening a PR.

- Commit messages
  - Use concise, conventional commits: `feat:`, `fix:`, `docs:`, `chore:`, `refactor:`.
  - Example: `feat(auth): add refresh token rotation support`.

- Review process
  - CI must pass before merging.
  - Maintain a respectful review tone; respond to review comments and push follow-ups to the same branch.

- Local setup
  1. `git clone git@github.com:istiakahmad62/istiakahmad62.git`
  2. `cd istiakahmad62`
  3. `npm install`
  4. `npm run dev`

If you’re unsure where to start, open an issue and label it `help wanted` — I’ll guide you.
